WHY THIS FILE EXISTS
--------------------
The README quotes one figure it cannot regenerate on every build, because
generating it costs an API call per phrasing: the classifier's accuracy on
24 phrasings that appear nowhere in the simulator. That figure is the whole
case for using a model rather than a lookup table, so the run it came from is
committed here instead of being asserted.

WHAT IS STILL VALID, AND WHAT IS NOT
------------------------------------
VALID -- the section "CLASSIFIER - phrasings absent from the simulator".
  24 cases, 24 model calls, 24 accepted, 22 correct (91.7%), 0 dangerous
  confusions. app/classifier.py and app/sim/classifier_eval.py have not been
  modified since commit 1b77124, so this is the same measurement the code
  would make today:

      git log --oneline app/classifier.py app/sim/classifier_eval.py

SUPERSEDED -- everything else below.
  The policy tables are single-seed point estimates from the old harness, and
  every one of their numbers has since moved for two independent reasons: the
  natural-recovery hazard leaked with polling cadence (the do-nothing anchor
  shown here as 21.6% is a polling artefact), and unclassified failures now
  route to a human instead of falling through to a retry. The current figures
  are twelve-seed means with confidence intervals; run the report.

  The in-world classifier section is also misleading as a *model* result:
  'model_calls': 0 means the lookup and an unreported cache answered all of
  it. Reporting cache hits separately is what commit 1b77124 fixed.

HONESTY NOTE
============
These are synthetic worlds, not merchant data. The claim is a
controlled comparison between policies under identical conditions --
not a forecast of real recovery for any merchant. Retry pricing is a
flat per-attempt fee and does not model card-scheme excessive-retry
penalties, which would penalise the retry-heavy baselines further.
